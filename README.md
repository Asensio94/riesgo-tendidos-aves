# Dynamic bird collision and electrocution risk map

Combines **power lines, pylons and wind turbines** from OpenStreetMap with **seasonal bird abundance**
(GBIF, which includes eBird), **GPS tracking** from Movebank and **topography**, to produce risk maps by
species and month plus a ranking of the individual assets (pylons, wind turbines, line segments) where
mitigation should be prioritised. Designed so that a utility, a public administration or an NGO can query
and refresh it without depending on a one-off survey.

## Status

Prototype v0.1 (September 2026). Runs without any API key. Movebank is optional.

**Website:** <https://asensio94.github.io/riesgo-tendidos-aves/> (project overview, method, open problems and roadmap) ·
[maps and rankings by region](https://asensio94.github.io/riesgo-tendidos-aves/regions.es.html). Rebuilt on the 2nd of every
month by GitHub Actions. The static presentation lives in `web/` and the thumbnails are generated by
`tools/thumbnails.py`.
Everything is published in Spanish and English: `index.html`/`index.en.html`, `regions.es.html`/`regions.en.html`
and, per region, `report.<lang>.html` and `map.<lang>.html`. The Spanish version is the default; the old URLs
(`regiones.html`, `<region>/informe.html`, `<region>/mapa.html`) redirect to it.
This file has a Spanish counterpart in [README.es.md](README.es.md).

## Usage

```bash
pip install -r requirements.txt
python -m birdrisk.cli run --region estrecho
```

Writes to `output/<region>/`:

| File | Contents |
|---|---|
| `report.es.html` / `report.en.html` | report with embedded map, seasonal table by species and top-ranked assets |
| `map.es.html` / `map.en.html` | interactive map (folium): monthly layers, layers by mechanism and by species, infrastructure and ranking |
| `ranking_elements.csv` / `.geojson` | every pylon, wind turbine and line segment with its peak index, mean index, peak month and species |
| `risk_total.tif`, `risk_electro.tif`, `risk_col_lin.tif`, `risk_col_aer.tif` | 12-band rasters (one band per month), EPSG:4326, for QGIS |
| `terrain.tif` | elevation, slope and TPI |

Useful options:

```bash
python -m birdrisk.cli regions                       # predefined regions (estrecho, tarifa, cantabria, monfrague, gallocanta)
python -m birdrisk.cli run --region cantabria        # a region may carry its own species list (config.REGIONS[...]["species"])
python -m birdrisk.cli species                       # species and weights
python -m birdrisk.cli run --bbox 39.6,-6.3,40.0,-5.7 -s "Aegypius monachus" -s "Ciconia nigra"
python -m birdrisk.cli run --region estrecho --movebank        # adds published Movebank datasets (downloads of hundreds of MB)
python -m birdrisk.cli run --region estrecho --study-id 123456 # specific Movebank studies (public, or with MOVEBANK_USER/MOVEBANK_PASSWORD)
python -m birdrisk.cli index                                   # rebuilds output/regions.es.html and regions.en.html and copies web/ (also run by `run`)
python -m birdrisk.cli score --region cantabria --observatory ../observatorio-alegaciones   # risk index of each project currently under public consultation
python -m birdrisk.cli score --region cantabria --geojson proyectos.geojson                  # or of any set of polygons
```

`score` returns, per project, the mean and maximum index, the peak month, the share of grid cells containing
infrastructure and the maximum per mechanism (`output/<region>/scored_projects.csv`). With `--observatory` it picks up
the geolocated notices from the [public consultation submissions observatory](../observatorio-alegaciones) and reuses its
cache of municipal boundary polygons.

## Sources

| Source | Use | Access |
|---|---|---|
| OpenStreetMap via Overpass | `power=line/minor_line` (voltage, operator), `power=tower/pole`, `generator:source=wind` | public, no key |
| GBIF occurrence API | records per species and month; records of all birds as sampling effort. Includes the eBird Observation Dataset | public, no key |
| AWS Terrain Tiles (terrarium) | ~30 m elevation → slope and topographic position | public, no key |
| Movebank Data Repository | published GPS datasets (CC0/CC-BY), search by species and CSV download | public, no key |
| Movebank API | public studies (`public/json`) or account-based (`direct-read`) | optional |

**eBird Status & Trends** (modelled weekly abundance at 3 km) is the best abundance layer available, but it requires
requesting a key and is distributed through R (`ebirdst`). It is already wired in as an option: download the
`*_abundance_median_3km_*.tif` GeoTIFFs with `ebirdst_download_status(<code>, pattern = "abundance_median_3km")`, copy them
into `data/ebirdst/<Genus_species>/`, and `birdrisk/ebirdst.py` reprojects them onto the grid, aggregates the 52 weeks into
months and blends them with the GBIF frequency (70/30, `EBIRDST_WEIGHT`). That species then gets confidence 1. With no files
present, nothing changes.

### Mortality data for calibration (pending)

There is no open nationwide dataset of electrocuted or collided birds. The most usable material found so far:

- Basque Government, *Avifauna y tendidos eléctricos* (power lines with line segments graded by hazard, shapefile CC BY 4.0):
  <https://www.geo.euskadi.eus/cartografia/DatosDescarga/Medio_Ambiente/Aves_y_Lineas_Electricas/KM_LINEAS_ASIGNADASAvesTendidos.zip>.
  Useful to validate the ranking on a `euskadi` region: check whether the line segments the administration flagged as
  hazardous come out at the top of our index.
- *Libro Blanco de la Electrocución* (Generalitat de Catalunya / Endesa, hazard criteria by pylon type):
  <https://mediambient.gencat.cat/web/.content/home/ambits_dactuacio/patrimoni_natural/fauna_autoctona_protegida/Publicacions/llibre_blanc_electrocucio.pdf>.
- Spanish Royal Decree 1432/2008 (measures against electrocution and collision on high-voltage power lines):
  <https://www.boe.es/buscar/act.php?id=BOE-A-2008-14914>.
- Monitoring programmes run by SEO/BirdLife and LIFE projects (Bonelli, AQUILA a-LIFE) publish aggregate figures rather
  than point locations; those would have to be requested.

Once mortality points are available, the planned fit is a logistic regression of the event against the cell's `electro` and
`col_lin` indices and the per-species weights, replacing the literature-derived weights with estimated ones.

## Method

For each species *s*, month *m* and ~0.5 km grid cell:

```
electro[s,m]  = P[s,m] · w_electro[s] · pylons_eq                  # distribution pylons ≤ 66 kV (RD 1432/2008)
col_lin[s,m]  = P[s,m] · w_col_lin[s] · line_km · (1 + relief)     # all conductors
col_aer[s,m]  = P[s,m] · w_col_aer[s] · n_turbines · (1 + ridge)
```

- **P** = density of records of the species / density of records of all birds, per month, smoothed and normalised to 0-1
  per species. Smoothing is adaptive: σ 1.5 km with ≥300 records in the month, and wider (σ·√(300/n)) with fewer, so that
  an isolated record in a rarely visited spot does not spike the index. Records repeated at the same point, month and year
  count as √n (an observer coming back is not n birds). Where Movebank GPS data exists it is blended with individual-days
  per cell, weighted 0.5·min(1, positions/2000): five positions from a passing bird do not move the map; thousands do.
- In the aggregate each species is weighted by **status × confidence**, with confidence = max(min(1, records/500),
  min(1, GPS positions/2000)), or 1 if an eBird Status & Trends model is loaded: a species with 250 records has an
  unreliable map and should not dominate the ranking, even though its own layers remain available.
- **pylons_eq** = pylons mapped in OSM or, where missing, 6 pylons per km of distribution line; capped at 20 per cell
  (anything above that is a substation). Each pylon carries a **hazard factor of 0.5-2** derived from its OSM tags
  (`material` wood 0.5; `line_attachment` pin 1.5 / anchor 1.3 / suspension 0.9; `line_management` branch, sectioning,
  transition to underground or line end 1.3; horizontal crossarms 1.1; portal structures 1.3), defaulting to 1.0 when
  there are no tags. The factor also scales the pylon's position in the ranking. In Cantabria roughly 5,000 out of 46,300
  pylons carry at least one such tag.
- **relief** = slope/25° (clipped to 1); **ridge** = normalised positive TPI (1.5 km radius).
- The per-species weights and the conservation weight live in `birdrisk/config.py` (a synthesis of Bevanger 1998,
  Janss 2000, Lehman et al. 2007, Marques et al. 2014 and the species list in Spanish Royal Decree 1432/2008). They are an
  adjustable starting point.
- Each index is rescaled to 0-100 (99th percentile of the region). The aggregate sums species weighted by status.
- The asset ranking takes the index of the cell holding each pylon/wind turbine, and the mean along each line segment.

## Pipeline

1. `osm.py`: Overpass (with mirrors), classification of power lines by voltage, voltage inherited by the pylons, rasterisation.
2. `terrain.py`: terrarium tiles → mosaic → slope and TPI → sampling onto the grid.
3. `abundance.py`: GBIF records downloaded in yearly blocks (newest to oldest, up to `GBIF_MAX_RECORDS` = 20,000 per species)
   with 3 threads and patient retries: GBIF's deep paging is slow and its API returns 503 under load. Sampling effort per
   0.05° tile and month via facets. Every block is cached so a run can resume.
4. `movebank.py`: DSpace repository (search, bitstreams, streaming bbox filter; files up to `MOVEBANK_MAX_MB` = 150 MB),
   `public/json`, `direct-read`.
5. `risk.py`: model, aggregation, asset ranking, seasonal table.
6. `report.py`: folium (one ImageOverlay per month), HTML report, GeoTIFF, GeoJSON.
7. `ebirdst.py` (optional): weekly eBird Status & Trends GeoTIFFs → months → blend with GBIF.
8. `score.py`: index statistics over project polygons (integration with the public consultation submissions observatory).
9. `site.py`: landing page `output/index.html`.

Everything is cached under `data/cache/`.

## Web service

`output/` is publishable as-is (static HTML + GeoTIFF/CSV) and is served at
<https://asensio94.github.io/riesgo-tendidos-aves/>.

GitHub Pages runs in **Actions mode** (`build_type=workflow`): the site is deployed straight from the workflow, with no
intermediate branch.

- `.github/workflows/monthly.yml` recomputes every region on the 2nd of each month and deploys `output/` with
  `actions/deploy-pages`. It can also be triggered manually:

  ```bash
  gh workflow run monthly.yml -R Asensio94/riesgo-tendidos-aves
  ```

- The download cache (GBIF, OSM, terrain) is carried across runs with `actions/cache`, so an ordinary run only re-fetches
  what has changed.
- **Movebank is kept out of the workflow**: downloads of hundreds of MB with frequent connection drops do not fit in a
  runner. Results that incorporate GPS data therefore only exist if they are computed locally. In the Strait, Movebank
  contributes ~300,000 black kite positions and ~65,000 white stork positions; in Cantabria the published datasets barely
  reach the area (5 honey buzzard positions), so the map there rests on records alone.
- `tools/publish.sh` packages `output/` and pushes it to the `gh-pages` branch. It is only useful if Pages is
  switched back to classic mode; while Actions mode is active the `gh-pages` branch is ignored.

## Limitations

- OSM coverage of pylons and voltages is uneven; hence the estimate of pylon counts where they are not mapped.
- Records carry observer bias (roads, viewpoints, hotspots). The sampling-effort correction attenuates it, it does not remove it.
- Record data carries no flight height; only some GPS datasets do.
- The index is relative to the region analysed, not a probability of mortality. It is meant for prioritising, not for certifying.
